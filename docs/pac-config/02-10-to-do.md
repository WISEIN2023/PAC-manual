# 2. Business Package Config (ZTPAC_CONFIG)

## 2.10 To Do

### 2.10.1 XTODO — To Do Active?

**테이블-필드:** ZTPAC_CONFIG - XTODO

**운영 설정(LG전자 특화) :** 모두 활성

#### 설정 설명

□ X설정 :  To Do 활성화

#### 참조 프로그램 / 오브젝트 (Where-used)

■ ZFPAC_OPEN_TODO/CLOSE_TODO(LZPAC260 U01/U02), ZFPAC_CIS_DISPLAY_SNID(LZPACCIS0010F01),

ZCL_PAC=>UPDATE_PAC_STATUS(CM01X), ZLPAC1000_F01/1011_F01, ZLPAC7191_F01

#### 프로세스 관점 분석 (사용 로직)

To Do 기능 활성화 여부(BusPkg 단위).

① ZFPAC_OPEN_TODO: 진입부에서 「SELECT SINGLE XTODO ... CHECK = 'X'」로 비활성 시 To Do 발송 자체를 skip → To Do 전체의 마스터 스위치.

② ZCL_PAC=>UPDATE_PAC_STATUS: 상태 변경 시 To Do open/close 호출 여부 결정.

③ Participant 화면(ZLPAC1000/1011)의 To Do 수신 설정 컬럼 활성화, Rework 배치(ZLPAC7191)의 Rework To Do 발송.

#### 영향도 분석 (변경 시 영향)

해제 시 해당 BusPkg의 To Do 발행/회수가 전면 중단 — 포털 To Do 기반으로 업무를 확인하는 담당자의 작업 누락 위험.

발송 채널(내부/외부 I/F)은 ZTPACSYS-TODOIF와 조합되어 동작하므로 함께 점검.

### 2.10.2 MREADY_LINK — Manual Ready Link Type

**테이블-필드:** ZTPAC_CONFIG - MREADY_LINK

**운영 설정(LG전자 특화) :** Subsidiary : R

#### 설정 설명

□ To Do 사용이 활성화된 경우 필드가 활성화된다

□ 메일, To Do를 통해 발송되는 Manual Ready의 링크 버튼을 클릭시 점프방법을 정의

- R(Result Screen) : 프로그램을 직접 실행하여 결과화면으로 바로 이동되게 한다

- ' '(Node on Map) : Map의 해당 노드로이동하여 직접 실행하여 프로그램을 실행하여야 한다

#### 참조 프로그램 / 오브젝트 (Where-used)

■ ZCL_PAC_MAIL=>SEND_MAIL_MREADY(CM00H)/SEND_MAIL_ERROR(CM00B)/SEND_MAIL_COMPLETE(CM00I)/SEND_MAIL_REWORK(CM00J)/

SEND_MAIL_CIS_CONTROLLER(CM008)/SEND_MAIL_CIS_REVIEWER(CM009), To Do 링크(LZPAC260F01)

#### 프로세스 관점 분석 (사용 로직)

메일/To Do로 발송되는 Manual Ready 링크의 유형(R:Report/M:Map 등).

① ZCL_PAC_MAIL의 각 SEND_MAIL_* 메소드가 「SELECT SINGLE FIORI_TILE, MREADY_LINK FROM ZTPAC_CONFIG」로 읽어, FIORI_TILE 기반 URL 구성 시 링크 타입에 따라 func_link(개별 실행화면) 또는 Map 화면 URL로 분기.

② To Do 본문 링크(LZPAC260F01)도 동일 로직.

#### 영향도 분석 (변경 시 영향)

잘못 설정 시 메일/To Do 수신자가 클릭한 링크가 의도와 다른 화면으로 이동 — 알람의 실효성 저하.

Fiori 화면 구성(개별 실행화면 사용 여부)과 일치시켜야 함.
