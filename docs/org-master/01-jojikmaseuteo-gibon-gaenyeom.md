# 1. 조직마스터 기본 개념

## 1.1 조직마스터란 무엇인가

PAC(Process Automatic Channel)는 결산 프로세스를 자동으로 수행하는 솔루션입니다. 결산을 **'어떤조직'**이 **'어떤비즈니스패키지(결산시나리오)'**로 수행하는지를 먼저 정의해야 하며, 이때 사용하는 기준 정보가 **조직마스터(Organization Master)**입니다.

조직마스터는 회사코드·사업영역·결산단위와 같은 실제 조직 정보와, 지역·국가·회사그룹·비즈니스 유형과 같은 분류 정보로 구성됩니다. 본 문서에서 다루는 11개 프로그램은 이 조직마스터 데이터를 등록·변경·삭제(유지보수)하거나, 조직 변경에 따라 결산 상태를 다시 맞추는(동기화) 프로그램입니다. 모든 프로그램은 패키지 ZPAC 에 속합니다.

## 1.2 PAC 조직 구조와 조직 레벨(PACLVL)

PAC의 결산 단위는 **비즈니스패키지(Business Package, BUPAK)**별로 관리됩니다. 각 비즈니스 패키지는 **조직레벨(PACLVL)**을 가지며, 이 레벨에 따라 결산을 관리하는 조직의 단위가 달라집니다. 조직 레벨 값은 소스(설정 테이블 ZTPAC_CONFIG 의 PACLVL 필드)에 다음과 같이 정의되어 있습니다.

| PACLVL 값 | 조직 레벨 | 관련 마스터 프로그램 |
|---|---|---|
| C | 회사코드(Company Code) | ZLPAC0018 회사코드 마스터 |
| B | 사업영역(Business Area) | ZLPAC0019 사업영역 마스터 |
| U | 결산단위(기타조직, Closing Unit) | ZLPAC0200 기타조직 정의 |

[표 1-1] 조직 레벨(PACLVL) 값 — 소스 상수 정의(ZLPAC0050/ZLPAC0200) 기준.

> 보완 설명 (SAP 표준·소스 확인)<br>위 값은 프로그램 소스에 선언된 상수(C_PACLVL_C='C', C_PACLVL_B='B' , C_PACLVL_U='U')에서 확인한 사실입니다.<br>비즈니스 유형(Business Type) 레벨(ZTPAC_BUSTY-BLEVEL)도 유사하게 A / C(회사코드) / B(사업영역) / K(결산단위) 로 구분됩니다.

## 1.3 조직마스터 프로그램 한눈에 보기

본 문서에서 다루는 11개 프로그램의 목록입니다. **트랜잭션코드**는 프로그램 명과 동일하게 부여되어 있으며(예: 프로그램 ZLPAC0013 → 트랜잭션 ZLPAC0013), 상태 동기화 배치 프로그램 2개(ZLPAC7192, ZLPAC7193)는 트랜잭션 코드가 없어 SE38 / SA38 또는 백그라운드 잡으로 실행합니다.

| 프로그램 | 트랜잭션 | 설명 | 유지보수/사용 테이블 |
|---|---|---|---|
| ZLPAC0013 | ZLPAC0013 | 비즈니스 유형(Business Type) 정의 | ZTPAC_BUSTY |
| ZLPAC0017 | ZLPAC0017 | 회사코드별 비즈니스 유형 정의 | ZTPAC_COM_BUSTY |
| ZLPAC0018 | ZLPAC0018 | 회사코드(Company Code) 마스터 유지보수 | ZTPAC_COM_MAST |
| ZLPAC0019 | ZLPAC0019 | 사업영역(Business Area) 마스터 유지보수 | ZTPAC_BA_MAST |
| ZLPAC0050 | ZLPAC0050 | 비즈니스 패키지에 조직 배정 | ZTPAC_CONFIG_COM/BA/UNI |
| ZLPAC0091 | ZLPAC0091 | 지역(Region) 마스터 유지보수 | ZTPAC_REGION |

## 1.4 유지보수 화면 공통 사용법 (ALV)

9개 마스터 유지보수 프로그램(0013·0017·0018·0019·0050·0091·0092·0093·0200)은 모두 동일한 **ALV그리드편집화면(화면번호0100)** 구조로 만들어져 있어, 조작 방법이 공통입니다. 각 프로그램 장에서는 반복 설명을 피하기 위해, 이 절의 공통 사용법을 전제로 프로그램별 차이점만 설명합니다.

1. 트랜잭션을 실행하면 조회 화면이 나타납니다. 선택 조건(있는 경우)을 입력하고 실행하면 기존 데이터가 ALV 그리드에 표시됩니다.
2. 화면 상단의 **[변경/조회]전환** 기능으로 편집 모드(EDIT_MODE = E)로 바꾸면 셀 입력이 가능해집니다. 조회 모드(D)에서는 데이터가 잠겨 수정할 수 없습니다.
3. 행 추가(신규), 셀 값 수정, 행 선택 후 삭제로 데이터를 편집합니다. 변경된 행은 좌측 **상태아이콘** 열에 변경/신규/오류 아이콘으로 표시됩니다.
4. **[저장]** 시 프로그램이 먼저 **잠금(Lock)**을 설정한 뒤 DB에 반영합니다. 중복 키가 있거나 필수값이 비어 있으면 해당 행에 오류 메시지가 표시되고 저장이 중단됩니다.
5. 삭제한 행은 저장 시 실제 테이블에서 삭제됩니다. 단, 해당 조직이 이미 다른 매핑(결산 배정 등)에 사용 중이면 삭제가 제한될 수 있습니다(소스의 ORG_MAP_EXIST 체크).

> 보완 설명 (SAP 표준·소스 확인)<br>각 테이블에는 변경 이력 필드(ERNAM/ERDAT 생성자·생성일, AENAM/AEDAT/AEZET 최종변경자·변경일·시각)가 공통 인클루드 ZSPAC_TIMESTAMP 로 포함되어, 저장 시 자동으로 기록됩니다.<br>삭제 플래그 LOEVM 를 가진 테이블은 물리적 삭제 대신 삭제 표시(논리 삭제)를 사용할 수 있습니다.
