# 7. 운영 · 유지보수 점검 가이드

## 7.1 조직마스터 등록 권장 순서

조직마스터는 서로 참조 관계가 있으므로, 다음 순서로 등록하면 참조 오류를 줄일 수 있습니다.

1. 기초 분류 마스터: 지역(ZLPAC0091), 국가(ZLPAC0092), 회사그룹(ZLPAC0093)
2. 비즈니스 유형: ZLPAC0013 (필요 시 ZLPAC0017 — 사용 여부 확인 후)
3. 조직 마스터: 회사코드(ZLPAC0018), 사업영역(ZLPAC0019), 기타조직/결산단위(ZLPAC0200)
4. 조직 배정: ZLPAC0050 로 비즈니스 패키지에 조직 배정
5. 구조 변경 후 필요 시: ZLPAC7192 / ZLPAC7193 로 결산 상태 동기화

## 7.2 증상별 점검 가이드

| 증상 | 우선 점검 사항 |
|---|---|
| 마스터 저장 시 오류/저장 안 됨 | ① 필수 키 값 누락 여부 ② 중복 키 여부(행에 오류 아이콘·메시지 표시) ③ 편집(변경) 모드 여부 ④ 잠금(Lock) 충돌 — SM12 확인 |
| 조직 삭제가 안 됨 | 해당 조직이 배정(ZLPAC0050)·결산에 사용 중인지 확인. 사용 중이면 소스의 ORG_MAP_EXIST 로 삭제가 제한됨 |
| 회사/사업영역 명이 안 보임 | SAP 표준 테이블(T001, TGSBT) 및 언어(SPRAS) 확인 |
| 비즈니스 유형이 선택 안 됨 | 상위 마스터 ZLPAC0013 등록 여부 및 유형 레벨(BLEVEL)이 대상 조직 레벨과 맞는지 확인 |
| 구조 변경 후 결산 상태가 안 맞음 | 변경 유형에 맞는 배치 실행 — 마스터 변경은 ZLPAC7192, Activity Group 이동은 ZLPAC7193 |
| ZLPAC0017 사용 관련 혼선 | 테이블 ZTPAC_COM_BUSTY DDIC 라벨이 ‘미사용’으로 표기됨 — 운영 사용 여부 확인 필요(3.2 참조) |

## 7.3 잠금(Lock) · 저장 관련 주의사항

> ⚠ 주의<br>유지보수 프로그램은 저장 시 잠금을 설정합니다(소스의 GV_LOCK_SUBRC). 다른 사용자가 같은 데이터를 편집 중이면 저장이 실패할 수 있습니다. 잠금 현황은 SM12 에서 확인하며, 잠금을 강제로 삭제하면 진행 중인 작업이 비정상 종료되거나 데이터 정합성 문제가 생길 수 있으므로 신중히 조치하십시오.<br>상태 동기화 배치(ZLPAC7192/7193)는 COMMIT WORK 로 즉시 DB에 반영되며 되돌리기가 어렵습니다. 대상 범위를 반드시 확인한 뒤 실행하십시오.
