# 9. 운영 · 유지보수 점검 가이드

모델링 관련 문의가 접수되면 아래 순서로 점검하면 원인 범위를 빠르게 좁힐 수 있습니다. 점검 항목은 SAP 표준 트랜잭션과 검증된 프로그램 동작을 기준으로 합니다.

## 9.1 정상 동작 확인 체크리스트

| 점검 항목 | 확인 방법 | 정상 기준 |
|---|---|---|
| 실행 환경 | SAP GUI(ActiveX)에서 실행 중인지 확인 | Web GUI 아님(모델링 4개 프로그램은 Web GUI 불가) |
| 관리 권한 | 해당 Business Package 관리 권한 보유 여부 | 권한 보유 → 편집 모드로 진입 |
| 조직 레벨 설정 | ZTPAC_CONFIG의 PACLVL/REQ_BUKRS 값 확인 | 의도한 레벨(C/B/U)로 설정됨 |
| 조직 등록 | ZLPAC0050에서 대상 조직이 등록되어 있는지 | 조직이 등록(활성)되어 있음 |

## 9.2 증상별 점검 가이드

| 증상 | 우선 점검 사항 |
|---|---|
| 프로그램 실행 즉시 메시지 후 종료 | ① Web GUI에서 실행 여부(S112) ② SAP GUI로 재실행 |
| 편집이 안 되고 조회 모드로만 열림 | ① Business Package 관리 권한 ② 다른 사용자의 잠금(SM12에서 EZ_ZSPAC_LOCK/ZTPAC_CONFCOM 확인) |
| '조직이 할당되지 않았습니다' 오류(S253/254/255) | ZLPAC0050에서 해당 회사코드/사업영역/결산단위 조직 등록 여부 확인 |
| Business Type 미정의 오류(E003/E091) | ZTPAC_BUSTY에 해당 Business Type 정의 여부, Business Package와의 연결 확인 |
| 표준으로 열어야 하는데 글로벌로 전환됨 | PCSGP=BUPAK 여부, GPID 존재 여부, BLEVEL='C' 여부 확인(3.4) |
| ZLPAC0050에서 Business Type 입력 불가 | 해당 조직에 이미 모델 매핑 존재 여부(LINK 아이콘), SPECIFIC BUSTY/결산단위 레벨 여부(6.4) |

## 9.3 잠금(Lock) 점검 시 주의사항

> ⚠ 주의<br>SM12에서 잠금을 강제로 삭제하면 편집 중인 사용자의 저장이 비정상 종료되거나 데이터 정합성 문제가 발생할 수 있습니다. 모델링 잠금(EZ_ZSPAC_LOCK), 조직 등록 잠금(EZ_ZTPAC_CONFCOM)은 정상 편집 중에도 표시될 수 있으므로, 실제로 사용 중인 사용자가 없는지 확인한 뒤에만 신중히 조치하십시오.

## 9.4 모델링 변경 이력 확인 — SCU3 (테이블 변경 로그)

PAC 모델링에는 **변경 이력을 직접 적재하는 전용 로그 테이블이 없습니다.** 따라서 "누가 · 언제 · 무엇을 바꿨는지"는 SAP 표준의 **테이블 변경 로그(Table ChangeLog /Log Data Changes)** 기능으로 확인해야 하며, 조회 트랜잭션은 **SCU3** 입니다.

**확인 절차**

1. **SCU3** 실행 후 테이블 변경 로그 평가(Evaluate Logs) 기능을 선택합니다.
2. 대상 테이블에 확인하려는 모델링 테이블을 입력합니다. 표준 모델은 ZTPAC_STD_NODE · ZTPAC_STD_LINK, 조직 모델은 ZTPAC_ORG_NODE · ZTPAC_ORG_LINK 입니다. (2.4 참조)
3. 조회 기간과 사용자를 지정하고 실행합니다.
4. 결과에서 변경 일시 · 변경 사용자 · 변경 전/후 값과 변경 유형(등록 / 변경 / 삭제)을 확인합니다.

> 주의 — SCU3에 이력이 보이지 않는 경우<br>테이블 변경 로그는 미리 켜져 있어야만 기록됩니다. 다음 두 가지 전제가 모두 충족되어야 합니다. ① 해당 테이블의 기술 설정(SE11 → 기술 설정, SE13)에서 '데이터 변경 로그 기록(Log Data Changes)' 가 활성화되어 있을 것, ② 시스템 프로파일 파라미터 rec/client 가 해당 클라이언트를 기록하도록 설정되어 있을 것.<br>로그는 설정을 켠 시점 이후의 변경분부터 기록됩니다. 설정 이전에 발생한 과거 변경은 SCU3로 조회할 수 없습니다.<br>모델링 테이블은 LOEVM 플래그를 사용하는 논리 삭제 방식이므로, 화면에서 "삭제"한 작업이 로그에는 레코드 삭제가 아니라 LOEVM 필드 값 변경(공백 → X) 으로 남습니다. 이력을 해석할 때 유의합니다.<br>로그 활성화는 성능과 DB 용량에 영향을 주므로, 적용 전 Basis 담당자와 협의하시기 바랍니다.<br>※ 참고 — DDIC에는 ZTPAC_NODE_HIST (PAC - Node Definition (Org Level) History) 테이블이 존재합니다. 다만 이 테이블이 모든 모델링 변경을 적재하는지 여부는 운영 시스템에서 확인이 필요하며(10장 현장확인 항목), 변경 이력 조회의 표준 수단은 SCU3 입니다.
